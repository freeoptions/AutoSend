# 发送到电脑

## 使用

1. 在电脑运行已交付的 Quicker「接收手机文件（AutoSend）」动作，设置接收目录、密码并启动服务。
2. AutoSend → 配置管理 → 设置 → 发送到电脑 → 电脑连接设置。填写电脑 IP 和自己设置的固定密码，测试连接后保存。新配置预填 `192.168.`，可以继续补全，也可以全部删除后填写其他网段的 IP。
3. 截图、相册或文件管理器 → 系统分享 → 发送到电脑。已配置时直接上传，成功后显示结果并返回来源应用。

也可在第一次分享时配置；配置在同一个接收 Activity 内完成，保存后继续本次上传。IPv4 简写使用默认端口 `17831`，其他端口填 `IP:端口`；保存与测试时自动转换成 Quicker HTTPS 域名，例如占位 IP `192.168.1.100` 转为 `https://192-168-1-100.lan.quicker.cc:17831`。完整 HTTPS 根地址仍支持粘贴，已有配置保持兼容；标准 Quicker 地址再次进入设置时显示为易编辑的 IP（非默认端口保留）。不自动发现或扫描电脑，不预设真实电脑或密码，实际传输继续使用 HTTPS，保留系统证书及主机名验证。

分享 Activity 和 intent-filter 均设置了「发送到电脑」标签，沿用 AutoSend 图标。系统分享面板及来源应用可以使用应用名、组合显示名称、缓存图标并自行排序，Android 应用无法保证各机型的显示名、图标样式或排序位置。

## 请求和认证

- 独立 OkHttp 客户端，直连（`Proxy.NO_PROXY`），不继承 Telegram 配置、不改系统代理。同一 Android 进程内的电脑分享及设置页复用专用客户端、线程和连接池，不为每次分享重建客户端；空闲连接按 OkHttp 默认边界释放，不新增后台保活服务。禁用自动网络重试、重定向和上传请求体重放。
- `POST /__api/upload`，标准 `multipart/form-data`，唯一文件字段 `file`，无 `path` 参数，保存到电脑服务根目录。
- 官方网页写 Basic，但本次电脑端交付文档声明 Quicker 2.3.17 使用 Digest MD5 / `qop=auth`。日常上传先用无文件副作用的 `GET /` 获取质询，随后直接携带认证发送一次文件 POST，不再额外请求目录首页验证密码；最终仍按 POST 的真实结果确认成功。设置页“测试连接”才额外发一次认证 `GET /`，确保不能仅凭质询就声称密码正确。MD5 摘要按 RFC 7616 计算，用户名固定 `quicker`。支持 Basic 质询作为旧服务兼容。未知 Digest 算法或认证失败会停止，不缓存/复用 Digest nonce，也不自动重传文件来协商认证。
- 若根页面未要求认证，测试会提示无法验证密码，不能将 HTTP 200 说成密码验证通过。连接测试不上传文件，不能证明落盘或上传接口可用。认证预检期间用户取消同样会取消当前网络请求。
- HTTP 200、严格布尔值 `success=true`、唯一 `files` 条目的 `name` / 根目录 `path` / 实际发送字节数全部吻合，且请求体读取完成，才确认成功。**真实 Quicker 2.3.17 响应不含 `fieldName`**，该字段缺省时不再报错，提供时仍须为 `file`。成功响应最多读取 65,536 字节。未收到有效成功结果时保留「结果未知」。
- **电脑端已实测同名文件会被覆盖**，与官方文档原先的描述存在差异。用户允许自动重命名。此前对随机候选名使用 GET/Range、等待 404 的检查曾在用户手机上拦截正常上传；该服务没有已确认的存在性查询协议，已移除该逻辑。现在每次上传都在原名主干后添加 32 位 UUID 后缀、保留扩展名，直接 POST 文件，不探测原名或候选名。手机原文件不改动；成功及异常提示显示本次实际使用的电脑文件名。
- 此服务没有原子的“仅不存在时创建”能力。完整 UUID 名称用于降低碰撞风险，不构成服务端保证。文件只 POST 一次；用户点击重试也可能产生另一份副本，应先检查电脑。
- 4xx 显示明确拒绝（408 超时保留结果未知）；5xx 的有效 `problem+json` 报错或 `success=false` 显示服务报告失败；其他不完整/不明确响应、发送后断连等提示文件可能已送达。重试由用户点击。

## 文件、密码与生命周期

- 仅接收 `ACTION_SEND` 的单个 `content://` 文件 URI（EXTRA_STREAM 或单项 ClipData）。不解析磁盘路径、不申请所有文件权限。
- 通过 ContentResolver 打开流，以 32 KiB 缓冲直接上传，不压缩、不转码、不落本地文件缓存。即使大小未知或元数据错误，也最多读取 100,000,001 字节、从不把超限部分交给上传流；已知大小超限时直接拒绝。
- 密码用 Android Keystore 中的 AES 密钥和 AES/GCM 加密，密文放在独立 SharedPreferences。该配置不参与原有任务导出，排除云备份和设备迁移。原有任务配置及导出格式保持原样。
- 按用户偏好，电脑设置和分享页面允许系统截屏及多任务预览，不设置 FLAG_SECURE。进入电脑设置会读取已保存密码并默认显示，可通过眼睛按钮切换隐藏；保存后继续显示。密码输入只保存在内存，不写 SavedStateHandle、rememberSaveable、Intent、日志或错误原文；本地加密保存及备份排除保持不变。恢复后密钥不可用时需要重新输入密码。
- Activity 的 ViewModel 保留一次传输，旋转或 Compose 重组不自动重发；系统保存状态中的 `uploadAttempted` 标记使进程恢复进入「结果未知」，等待手动操作。临时 URI 读取授权丢失时需要重新分享，没有后台恢复或断点续传。
- 页面离开前台（旋转除外）取消网络请求及文件流；没有常驻服务。成功后 `finish()` 返回，不启动首页、不使用清空任务栈或结束宿主任务的 API。应用内设置 Activity 返回原配置页；主页面导航状态可恢复。
- 上传中取消/返回先显示确认，提醒文件可能已送达；确认后取消。配置未保存时返回提示放弃修改。系统返回依赖 AndroidX BackHandler，在手势提交时消费；弹窗与输入法由各自的系统返回层处理。预测返回取消、来源应用栈及机型差异仍需真机核查。

## 验证边界

电脑设置页提供“复制最近上传日志”，也可在 Android Studio Logcat 按 `AutoSendComputer` 筛选。每次上传/测试完成输出一条汇总，记录最近 20 条（单条最多 1800 字符，约 36 KB），不进入任务发送日志、配置导出、云备份或设备迁移。日志只含耗时、字节数、HTTP 状态、固定阶段与匿名本进程编号，不含电脑地址/IP、文件名、URI、密码、Authorization、nonce、响应正文或异常原文。OkHttp 事件回调只记录内存数据，结束后输出；诊断写入失败不改变上传结果。

字段含义：

- `client_init_ms`：本页面创建客户端包装器及首次共享客户端初始化耗时；客户端在页面生命周期内重用，所以它是初始化观测值。
- `metadata_ms`、`settings_ms`：读取分享文件元数据、读取地址和解密密码的前置耗时。
- `total_ms`：创建本次发送尝试到校验响应结束的耗时；不包含上面三个前置观测值、整个 Android 应用冷启动，也不包含成功页面原有的 1 秒停留。
- `auth_ms`：本次获取认证质询／测试验证的耗时；`source_open_ms` 为打开 ContentResolver 流的时间；`validate_ms` 为接收及校验响应的耗时。
- `AUTH_CHALLENGE`、`AUTH_VERIFY`、`UPLOAD`：各网络请求的耗时、HTTP 状态及 `connection=new/reused/not_acquired`。正常 Digest 上传只有 `AUTH_CHALLENGE` 和 `UPLOAD`，测试连接才有 `AUTH_VERIFY`。
- `dns_ms`、`connect_ms`、`tls_ms`、`body_ms`、`response_wait_ms`：DNS、建立连接、TLS、发送请求体（包含打开和读取内容流）、请求发送完成到收齐响应头的时间。`connect_ms` 包含 TLS，`body_ms` 包含流读取，阶段有嵌套，不能简单相加；复用连接时 DNS/连接/TLS 回调可能不发生，相应显示 0。失败时尚未完成的阶段记录截至请求结束的耗时。

`python -B tools/check_computer_upload.py` 使用本机已有 JDK、Kotlin/OkHttp/Gson 缓存：编译实际上传、认证与计时代码，通过不调用 `proceed` 的应用拦截器验证请求、Digest 标准算例及真实 POST 摘要、认证失败、响应分类、大小边界和取消，再解析新增/关联 Kotlin 及 XML。包含用户提供的两份真实成功 JSON（普通文件名、中文加空格，均无 `fieldName`），并验证重复分享生成不同 UUID 名称、不发文件存在性 GET、正常上传只有一次质询和一次文件 POST；设置测试继续验证密码。另以可控时钟验证计时事件、连接新建/复用标记、日志脱敏及日志异常不影响上传。不会下载依赖、运行 Gradle、建立局域网连接或启动 Android。

IP 输入检查另覆盖可编辑默认前缀、其他网段、默认及自定义端口、无效/不完整 IP、完整 HTTPS 地址兼容和设置回显，并用拦截器验证 IP 简写实际构造为 Quicker HTTPS 请求；未执行真实 DNS 或网络连接。

用户已确认 UUID 名称上传可落盘，也曾反馈等待进度开始约 3–4 秒，真正传输很快。IP 简写输入、连接池共享、去除额外认证验证请求及耗时日志尚未构建或真机验证，不能据离线检查声称实际提速。后续应对比首次与连续分享的日志，区分 DNS/连接/TLS、认证和文件流读取；其余待测包括约 20 MB、接近上限、传输中断、未知大小 URI、原/收文件 SHA-256，以及旋转/后台取消/左右边缘返回/取消预测返回/系统返回键。
